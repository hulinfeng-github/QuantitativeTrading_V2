# ⚡ QuantitativeTrading 2.0 (A股智能量化投研与实战交易系统 2.0)

> 本项目是个人研究与人工决策辅助工具，包含技术指标、启发式评分、行情监控和本地账本。策略尚无足够的、经过独立复核的实盘证据证明具有正收益；历史回测也不能保证未来表现。系统不连接券商、不自动下单，推送和止损价均为提示，成交、涨跌停排队、滑点和资金约束需由使用者自行核实。

> “主力筹码”“情绪温度”“封板硬度”等名称表示代码中的代理指标或规则评分，不代表系统能识别真实账户、资金意图或未来收益。行情/财报接口可缺失、延迟或调整，缺失数据按未知处理，不应解读为低风险。

## 📅 自动化操盘实战作战日程表 (Trading Day Timetable)

系统内置工作日定时调度。节假日与临时休市日历没有完整接入；T0、涨停候选、尾盘候选和样本达标后的参数优化默认开启。当前程序只跟踪信号并推送提醒，不会自动提交交易委托。

```
09:28 ─── 🌅 对手工确认的实际成交记录发送早盘行情提醒
09:30 ─── 🔔 开盘启动盘中自选巡检 (每 5 分钟检查：持仓风险提醒、波段研究信号与T0候选)
09:35 ─── ⚡ 涨停候选扫描与研究摘要推送 (自动开启；受市场状态和信号门槛过滤)
14:32 ─── ⚡ 尾盘策略候选扫描 (自动开启；日线数据无法验证14:30实际成交)
14:48 ─── ⚠️ T0尾盘模型状态核验提醒 (提示不代表已成交或应平仓)
15:10 ─── 📊 收盘复盘与信号跟踪更新 (自动优化开启；样本不足时不调参)
15:30 ─── 💎 全市场主板多因子共振选股 + 财报排雷深度体检 (推送次日重点关注精选组合)
```

## 🚀 1.0 vs 2.0 核心演进对比

| 维度 | 1.0 版本机制 | 2.0 升级版本机制 (GitHub 优秀开源方案融合) |
| :--- | :--- | :--- |
| **因子体系** | 单一修正 RSRS + 简单均线与传统 MACD | **Qlib 启发式 Alpha 因子库 + 偏度修正 RSRS 2.0**（20日量价相关性、动量加速度、标准化 ATR、相对极值通道） |
| **RSRS 算法** | 基础 OLS 回归与滑动 $Z\text{-score}$ | **残差分布偏度 (Skewness) 过滤惩罚**，有效过滤诱多尖刺与日内假脉冲假突破 |
| **筹码分布 (CYQ)** | 基础换手率衰减模型 | 使用日线成交量分布的估算型指标；不是实际账户持仓或真实“主力成本”数据 |
| **财报基本面体检** | 无财报分析 | 基于单一公开行情服务字段的启发式比率；字段不全时明确报告未知并阻止新开仓信号 |
| **游资龙虎打板** | 无打板模块 | 规则评分和本地信号跟踪台账；自动推送开启，跟踪样本不等于真实成交 |
| **尾盘突袭战法** | 无尾盘机制 | 日线/行情字段启发式筛选；自动扫描开启，日线代理估算无法验证14:30成交和早盘路径 |
| **大盘宏观择时** | 简单上证指数 MA60 单一二元滤网 | 宏观状态过滤；未知或数据过期时不建议新增敞口，配置总仓位上限为牛市 65%、震荡 35%、弱市 10% |
| **日内做T机制** | 静态 $\pm 1.5\%$ 分时均线偏离度 | 研究性 VWAP/布林规则；自动监控开启，要求趋势、分时反转、数据新鲜度与可卖数量条件 |
| **仓位与组合风控**| 简单固定仓位 | ATR止损风险预算和半凯利上限；缺少至少30笔去重且已结算样本时禁止给出新仓建议 |
| **历史回测引擎** | 单股日线近似回测 | 按前一日信号、次日开盘和日线止损估算；不还原 ST/新股/停牌/盘口队列，末段收益不是独立盲测 |
| **可视化与前端** | 原生简单 Canvas 画布 | **Bloomberg/TradingView 风格暗黑终端**，集成 **Apache ECharts 5** 专业 K线、分时 VWAP、筹码分布与净值对比曲线 |
| **参数调整** | 人工调整 | 自动优化开启；至少30笔已结算样本后才可能改参，信号样本仍不等于真实成交 |

## ⚡ 核心子策略与量化模型详解

### 1. ⚡ 涨停候选日线筛选与信号跟踪 (`LimitUpEngine`)
此模块包含涨停板型规则评分和信号跟踪台账。自动扫描与研究摘要推送默认开启，并受市场状态和评分门槛过滤；台账不预填演示交易，推荐信号及后续行情记录不代表真实成交或真实收益。

#### A. 5 大主板涨停板型分类识别
1. **首板形态**：按日线涨幅与前序行情分类，不评估高位监管风险或成交安全边际；
2. **1进2形态**：按相邻交易日日线涨停幅度估算，不识别资金共识或换手质量；
3. **2进3形态**：按日线连续涨幅估算，高位波动和流动性风险较大；
4. **高位连续涨停形态**：日线连续涨幅估算，不判断龙头身份；
5. **反包形态**：按前一日上影线和当日涨幅估算，不推断洗盘或资金回补。

#### B. 日线技术规则分
评分由涨停形态、日成交量变化和均线位置组成。它不读取分时封板时间、封单金额、炸板回封次数或盘口队列，不能解释为“封板硬度”或成交概率。

#### C. 信号跟踪台账与导出
- **存储路径**：
  - JSON 核心数据：`storage/limit_up_trades.json`
  - 电子表格：`storage/limit_up_ledger.csv`（UTF-8 with BOM 编码）
- **根据后续行情更新信号跟踪字段**：
  每日 15:10 收盘复盘时，系统可拉取前一交易日信号标的的次日开盘价、最高价、收盘价并更新跟踪记录：
  - **次日开盘、最高、收盘价相对信号日收盘参考价的变动**（未扣成本，不代表成交）
  - **次日继续涨停的日线估算状态**
  - **信号样本的价格变动分布**（不含真实成交验证，跌幅 $\ge 4\%$ 作为统计分组）

#### D. 风险边界
涨停板排队可能无法成交，炸板或次日低开时也可能无法按提示价格退出。分时封单、封成比和打分不构成高胜率证明；界面中的信号不是经过验证的买卖指令。该模块默认自动扫描并推送候选研究摘要，具体信号仍受市场状态过滤。

### 2. 📊 深度经营状况财报分析与六维排雷引擎 (`FinancialEngine`)
收盘选股后读取可用财务字段并计算启发式指标。数据源缺失或关键排雷字段不全时，结果标记为未知并暂缓新开仓信号；指标本身不能保证财报完整或基本面安全：
- **杜邦 3 因子核心分解矩阵**：
  $$\text{ROE} = \text{销售净利率 (Net Margin)} \times \text{总资产周转率 (Asset Turnover)} \times \text{权益乘数 (Equity Multiplier)}$$
  自动归因企业盈利模式（高净利护城河型 / 高周转运营型 / 杠杆驱动型）；
- **Piotroski 风格字段提示**：
  展示个别字段规则命中情况，不输出完整9项 F-Score 数值；当前数据源缺少可比股本序列，稀释项无法判断；
- **A 股专属六维财务避雷排雷雷达**：
  - 商誉减值隐患：商誉/净资产 $\ge 20\%$ 预警；
  - 应收账款坏账风险：应收账款/营收 $\ge 35\%$ 警惕；
  - 存货积压跌价：存货/总资产 $\ge 40\%$ 警惕滞销跌价；
  - 现金流与净利润匹配度：经营净现金流 / 归母净利润 $< 0.3$ 严厉惩罚“纸面富贵”；
  - 重资产高负债断裂危机：资产负债率 $\ge 78\%$ 严控流动性危机；
- **企业画像与风险过滤**：
  画像是规则归类，不是投资评级。关键财务数据未知时不将缺失值解释为安全，并在选股信号中降级观察。

### 3. ⚡ 尾盘策略研究模块 (`TailStrategy230`)
该模块按行情接口字段生成候选信号并提供日线代理回放。回放在 T 日收盘生成信号、用 T+1 开盘价作为代理入场，并用 T+2 日线 OHLC 模拟退出，以遵守 A 股买入证券交收前不可卖出的规则。自动扫描默认开启但不会提交委托；日线无法验证 14:30 实际成交、次日早盘价格路径、涨跌停排队或真实滑点，结果不证明策略具有正期望。

---

### 4. 🎯 实验性日内做T研究模块 (`T0SmartEngine` & `T0GroupManager`)
此模块使用 VWAP 与日内波动规则生成研究信号，**自动监控与尾盘核验提醒默认开启**。入场要求至少30条有效且不超过5分钟延迟的分时数据、60个已完成日线bar、趋势与反转确认、账户已核实的可卖股数；单次模型数量受底仓比例和上限约束。信号台账是模型状态，不代表真实成交、实际可卖数量或账户盈亏，也不是自动买卖或强平指令。
- 动态布林与 VWAP 偏离仅为规则条件，未经过含费用、可成交性和样本外验证；
- 模型记录不等于用户已下单或成交，价格和数量仅作参考；
- 尾盘模型状态提醒默认开启，但只要求核对实际持仓与委托，不会自动提交委托或平仓。
- **🏷️ 做T标的分组、多钉钉群分流与策略模块级订阅控制 (Group Routing & Module Switches)**：
  - 支持将需要做T的股票划分为不同组（如「科技芯片组」、「低波红利ETF组」、「有色周期组」等）；
  - 每个分组可独立配置专属钉钉群机器人 Webhook 与加签 Secret，各组标的日内做T信号**精准独占推送到该组对应钉钉群**；
  - **模块级使能与关闭开关**：每个群支持单独开关：
    - `日内做T` (`push_t0`)
    - `盘中盘后多因子选股` (`push_screener`)
    - `尾盘 2:30 突袭战法` (`push_tail230`)
    - `游资龙虎榜打板` (`push_limitup`)
    - `每日收盘定制复盘` (`push_review`)
    各群可根据业务关注点自由勾选接收的消息类型，彻底阻断不相关模块骚扰；
  - **定制化分组收盘复盘报告**：每日收盘报告按各分组专属标的自动筛选，仅汇报归属于该组的自选股票与做T战绩，并严格根据该组启用的功能模块总结细分，实现群专属定制化日报推送；
  - **交互体验重构**：管理弹窗中点击任意分组卡片即可即时切换右侧完整详情（名称、Webhook、Secret、启用状态、5 大模块订阅开关、标的勾选列表），免除查找点击编辑按钮的繁琐步骤；
  - 钉钉推送卡片头部清晰标注组名（如 `【量化2.0 · 科技芯片组】通富微电`），有效解决单一大群股票繁杂、消息刷屏与混乱问题；
  - Web 界面提供分组快捷筛选、股票批量分组、一键钉钉连通性测试与即时切换；
- **🛡️ 钉钉官方 20条/分 频控安全卫士与多标的聚合推送 (Rate Limiting & Signal Aggregation)**：
  - **滑动时间窗口平滑限流 (19条/分)**：钉钉官方机器人有每分钟最多 20 条消息的严格上限，超过将被强制封禁 10 分钟。系统内置毫秒级滑动时间窗口限流器，单 Webhook 严格限制在 19 条/分以留出安全余量，相邻外发请求保持至少 1.0 秒间隔，杜绝突发并发 (burst) 触发官方流控；
  - **10 分钟自动熔断保护**：一旦捕获钉钉官方 130101 / 88 / 429 频控报警，自动激活 10 分钟熔断冷却，拦截外发并给出显式警报，防止盲目持续重试导致官方惩罚期延长；
  - **多标的智能合并聚合卡片**：当同一分钟内多只标的密集触发做T/止损/买卖信号时，系统自动将同一 Webhook 目标群的信号聚合成单张 Markdown 卡片（`【量化2.0】多标的量化交易指令聚合`）一次性推送，直接降低 80%~90% 的消息外发量，彻底根治群刷屏与频控超限问题；
  - **透明监控 API**：提供 `/api/dingtalk/status` 实时查看当前 60 秒已发量、剩余可用额度及各群机器人状态。

### 5. 💎 多因子共振波段模型 (Alpha + RSRS 2.0 + CYQ 2.0)
- **偏度修正 RSRS 2.0 算法 (Skewness-Penalized RSRS)**：
  对过去 18 天高低价 OLS 回归斜率 $\beta$ 进行滑动 600 天 $Z\text{-score}$ 标准化，并引入金工残差偏度修正（Skewness Penalty），有效过滤诱多尖刺与日内假脉冲；
- **金工 CYQ 2.0 主力筹码集中度**：
  精确计算 70% 与 90% 筹码集中度 (SCR) 与获利盘比例，捕捉单峰密集且获利盘 $>70\%$ 的主力起爆黄金点；
- **现代化组合风控**：
  ATR距离控制单笔风险预算，半凯利仅作仓位上限；没有足量去重且已结算样本时不生成开仓建议。

## 🛠️ 安装与快速上手

### 1. 环境要求
- Python **3.10+**（推荐 3.10 / 3.11）
- 能访问国内行情接口的网络（腾讯 / 新浪 / 东方财富）
- 无需数据库，所有数据以 JSON 形式保存在本地数据目录

### 2. 安装依赖
```bash
# 1) 克隆仓库
git clone <你的仓库地址>
cd QuantitativeTrading_V2

# 2) 创建并激活虚拟环境
# Windows (PowerShell)
python -m venv .venv
.\.venv\Scripts\Activate.ps1
# macOS / Linux
python3 -m venv .venv
source .venv/bin/activate

# 3) 安装依赖
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

> **依赖说明**：`fastapi`/`uvicorn` 提供 Web 服务；`pandas`/`numpy`/`scipy` 负责因子与筹码计算；`apscheduler` 负责定时调度；`requests`/`httpx` 负责行情与推送；`watchfiles` 仅在 `--reload` 开发模式用到，未安装会自动降级。

### 3. 启动
```bash
python main.py
```
浏览器打开 **http://127.0.0.1:8089**。

**首次启动会自动完成**：
- 创建空白配置与自选池（无需手动准备任何数据文件）；
- 联网拉取沪深主板股票池；若行情接口暂时不可用，会自动降级为内置核心标的池，稍后自动恢复；
- 默认不启用任何推送渠道（需在 Web 控制台「⚙️ 策略与推送配置」里填写自己的钉钉/微信参数）。

### 4. 隐私与个人数据隔离（重要）
个人数据与代码严格分离，默认不会上传到任何仓库：

| 内容 | 位置 | 是否入库 |
|---|---|---|
| 个人持仓、成本、可卖数量 | `storage/watchlist.json` | ❌ |
| 钉钉/微信 Webhook 与密钥 | `storage/user_config.json`、`.env` | ❌ |
| 做T分组与分组群机器人 | `storage/t0_groups.json` | ❌ |
| 交易流水、复盘历史、行情缓存、日志 | `storage/*.json`、`*.csv`、`*.log` | ❌ |
| 配置与自选池模板 | `storage/*.example` | ✅ |

`.gitignore` 已按「`storage/*` 全部忽略、只保留 `*.example`」处理。

如需把个人数据彻底放到仓库之外（云服务器部署推荐），设置环境变量：
```bash
# Windows PowerShell
$env:QUANT_DATA_DIR="D:\quant_private_data"
# macOS / Linux
export QUANT_DATA_DIR=/path/to/quant_private_data
```
系统会把全部个人数据写入该目录，仓库目录保持干净、可直接公开。

### 5. 可选：环境变量
```bash
cp .env.example .env      # Windows: copy .env.example .env
```
可配置 `WEB_PORT`、`WEB_HOST`、`DINGTALK_*`、`WECHAT_*` 等；`.env` 已被 git 忽略。

### 6. 停止与重启
服务默认单进程运行，`Ctrl+C` 即退出并立即释放端口。若异常退出后再次启动提示端口被占用：
```bash
python main.py --stop      # 结束占用 8089 端口的残留进程
python main.py --restart   # 先结束残留进程，再重新启动
```
也可双击根目录的 `stop_server.bat`。启动时若检测到占用者正是本系统上一次遗留的进程，会自动清理后再启动；若被其他程序占用则明确提示并中止，避免“看起来启动成功、页面却一直转圈”的假启动。开发调试需要热重载时再手动加 `--reload`（Windows 下会额外常驻一个监督进程，日常运行不建议开启）。

### 7. 命令行快捷操作
- **运行项目自带测试套件**（结果取决于当前环境和数据依赖）：

  ```bash
  python main.py --backtest --symbol 601138 --days 600
  ```
- **立即执行每日收盘全景复盘与参数自进化 (输出 Markdown 长文报告与更新账本)**：
  ```bash

  ```
- **测试钉钉/微信消息推送通道**：

## ❓ 常见问题与解答 (FAQ)

### Q1: 为什么有时候收盘选股雷达没有推送股票？
- **A**: 策略严格设定了多重安全门槛：
  1. **大盘情绪熔断**：当大盘情绪温度计 $< 15$ 分（处于“极度冰点”或“系统性杀跌”通道）时，策略会自动收缩甚至归零风险敞口，杜绝弱市逆势接盘；
  2. **多因子共振与财报排雷**：要求修正 RSRS 突破买点、主力筹码集中度 $\le 12\%$、且杜邦净利率坚挺、无商誉高危或坏账隐患。若当日全市场无标的满足共振标准，系统会发出“今日保持空仓防守”提醒，绝不滥发低质量信号。

### Q2: 财报与经营状况数据来自哪里？财报更新后会自动同步吗？
- **A**: 财报数据直接对接东方财富与新浪财经官方披露接口，实时解析最新资产负债表与利润表。系统内置增量更新机制（本地持久化于 `storage/financial_cache.json`），上市公司发布一季报、中报、三季报或年报披露后，系统会自动检测更新时间戳并刷新指标，杜绝滞后。对 ETF 基金已自动内置免疫过滤规则。

### Q3: 导出的打板表格在 Windows 上用 Excel 打开为什么不会乱码？
- **A**: 系统在导出 `storage/limit_up_ledger.csv` 时采用了工业标准的 **`utf-8-sig` (带 UTF-8 BOM)** 编码。Microsoft Excel 与 WPS 会自动识别 BOM 签名，无需在导入向导中繁琐设置编码，双击即可直接秒开。

### Q4: 执行 `python main.py` 卡住、浏览器一直打不开怎么办？
- **A**: 绝大多数情况是上一次进程没有真正退出，仍占用 `8089` 端口。Windows 允许在端口已被监听时重复绑定（`SO_REUSEADDR`），所以新进程会打印“Uvicorn running on ...”却收不到任何请求，看起来像卡死。处理方式：
  1. 直接执行 `python main.py --stop`（或双击 `stop_server.bat`）结束残留进程；
  2. 再执行 `python main.py` 启动。当前版本会在启动前用独占方式探测端口，若占用者正是本系统的遗留进程会自动清理，若是其他程序则明确报错并中止，不会再出现“假启动”；
  3. 想一次性完成“停掉旧的 + 启动新的”，用 `python main.py --restart`。
  另外服务已默认关闭热重载：`--reload` 会在 Windows 下额外常驻一个 uvicorn 监督进程，Ctrl+C 时偶发未被回收，正是端口残留的常见来源，仅在开发调试时使用。

### Q5: 如何配置钉钉和微信机器人推送？
- **A**: 在 Web 控制台右上角切换到 **`⚙️ 策略与推送配置`** 标签：
  - **钉钉**：填入群机器人的 WebHook 地址与加签密钥（Secret），点击保存并测试；
  - **微信**：支持免费的 PushPlus（微信公众号弹窗，推荐，免装 App）、Server酱或企业微信群机器人，填入 Token 保存即可。
